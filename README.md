# CS2 Cheatsheet

Личная шпаргалка по раскидкам, позициям и стратегиям для CS2. Статический
сайт — никакого сервера, никакой базы данных, никакой сборки. Открываешь
`index.html` (или деплоишь на Netlify/GitHub Pages) — и всё работает.

## Как это устроено (архитектура)

```
cs2-cheatsheet/
├── index.html              главная страница со списком карт
├── map.html                страница одной карты (позиции + раскидки + стратегии)
├── css/
│   └── style.css           все стили, тёмная тактическая тема
├── js/
│   ├── main.js             логика главной страницы
│   └── map.js              логика страницы карты (маркеры, фильтры, вкладки)
├── data/
│   ├── maps-index.json     список карт для главной страницы
│   └── maps/
│       ├── mirage.json     ПОЛНЫЙ пример: позиции, раскидки, стратегии
│       ├── inferno.json    заготовка-шаблон (1 раскидка для примера)
│       ├── ancient.json    заготовка-шаблон
│       └── ...              остальные карты — тоже заготовки
└── images/
    └── maps/
        ├── mirage.svg       схематичная картинка карты (абстрактная, не скриншот из игры)
        └── ...
```

**Никакого бэкенда нет.** Всё содержимое — это JSON-файлы в `data/maps/`.
Хочешь добавить раскидку — открываешь файл текстовым редактором (даже
блокнотом), копируешь один блок и меняешь текст. Сайт сам подхватит
изменения при перезагрузке страницы.

### Почему не CMS/админка

Ты сказал, что важно, чтобы добавлять контент мог человек без опыта в
программировании. Форма-админка потребовала бы отдельного бэкенда (базы
данных, сервера, авторизации) — а это лишняя сложность и лишний хостинг.
Вместо этого мы держим контент в JSON: редактировать текстовый файл проще,
чем кажется, а гарантированно проще, чем разворачивать и поддерживать
сервер. Если через какое-то время появится желание — админку можно
добавить позже (см. раздел "Как расширять" в конце).

## Как добавить новую раскидку

Открой `data/maps/<карта>.json` и найди массив `"lineups"`. Скопируй один
блок и вставь новый, поменяв поля:

```json
{
  "id": "l013",
  "positionId": "b_site",
  "type": "smoke",
  "title": "Смок в окно с Т-спавна",
  "description": "Встань у ящика, прицелься в антенну, кидай прыжком.",
  "video": "https://www.youtube.com/embed/ID_ВИДЕО",
  "image": ""
}
```

Поля:
- **id** — любая уникальная строка (просто чтобы не совпадала с другими).
- **positionId** — должен совпадать с `id` одной из позиций карты (смотри
  массив `"positions"` в том же файле).
- **type** — один из: `smoke`, `flash`, `molotov`, `he`.
- **title** — короткое название, видно в карточке.
- **description** — как кидать и зачем.
- **video** — ссылка на YouTube в формате **embed**: замени в обычной
  ссылке `watch?v=` на `embed/`. Например
  `https://www.youtube.com/watch?v=XXXX` → `https://www.youtube.com/embed/XXXX`.
  Можно оставить пустой строкой, если видео нет.
- **image** — путь или ссылка на картинку/гифку. Можно оставить пустым.
  Если кладёшь свои скриншоты — сложи их в `images/lineups/` и укажи
  путь вида `images/lineups/mirage-b-smoke.png`.

## Как добавить новую позицию на карте

В том же файле, в массиве `"positions"`, добавь:

```json
{ "id": "new_spot", "name": "Новая точка" }
```

И укажи, где она находится на изображении карты, в объекте
`"positionCoords"` (в процентах от левого верхнего угла картинки,
0–100):

```json
"new_spot": { "x": 42, "y": 60 }
```

Проще всего подобрать координаты — открыть картинку карты, прикинуть на
глаз (0% — левый край/верх, 100% — правый край/низ) и подправить после
того, как посмотришь на сайте, куда попал маркер.

## Как добавить стратегию

В массиве `"strategies"` того же файла:

```json
{
  "id": "s003",
  "title": "Быстрый выход A через смоки",
  "side": "T",
  "summary": "Короткое описание идеи стратегии.",
  "roles": [
    { "role": "Энтри", "player": "Первый заходит на позицию" },
    { "role": "Саппорт", "player": "Кидает дым и молотов" }
  ],
  "steps": [
    "Саппорт кидает дым на 15 секунде.",
    "Энтри заходит следом за дымом.",
    "Команда доигрывает кроссфаер на сайте."
  ],
  "video": ""
}
```

## Как добавить целую новую карту

1. Скопируй `data/maps/inferno.json` (это заготовка) под новым именем,
   например `data/maps/train.json`, и поменяй `id` и `name` внутри.
2. Добавь картинку схемы в `images/maps/train.svg` (или .png/.jpg —
   подойдёт любой формат, главное укажи правильное расширение в поле
   `radarImage`).
3. Добавь карту в список `data/maps-index.json`:
   ```json
   { "id": "train", "name": "Train", "thumb": "images/maps/train.svg" }
   ```

Готово — карта появится на главной странице автоматически.

## Про картинки карт

Схемы карт в `images/maps/*.svg` сейчас — это абстрактные плейсхолдеры
(просто прямоугольники-комнаты), а не скриншоты из игры. Это сделано
специально, чтобы не использовать чужие графические материалы напрямую в
шаблоне.

Для точных раскидок советую заменить их на свои скриншоты оверлей-карты
(radar) — это твой личный некоммерческий инструмент для команды, так что
можно смело брать скриншот прямо из игры (Настройки → Игра → Radar, или
скриншот overview-карты) и положить файл с тем же именем в `images/maps/`.
Формат (svg/png/jpg) не важен, главное — чтобы имя файла совпадало с тем,
что указано в поле `radarImage` внутри JSON карты.

## Запуск локально

Файлы обычные, без сборки — но браузеры блокируют `fetch()` JSON-файлов
при открытии `index.html` напрямую с диска (`file://`). Поэтому запускай
через любой простой локальный сервер:

```bash
# вариант 1: Python (обычно уже установлен)
cd cs2-cheatsheet
python3 -m http.server 8000
# затем открой http://localhost:8000

# вариант 2: Node (если есть npx)
npx serve .
```

## Деплой на Netlify (проще всего)

1. Зарегистрируйся на [netlify.com](https://www.netlify.com) (можно через GitHub).
2. На дашборде нажми **Add new site → Deploy manually**.
3. Перетащи папку `cs2-cheatsheet` (всю целиком) в область загрузки.
4. Через несколько секунд сайт будет доступен по ссылке вида
   `https://your-site-name.netlify.app`.
5. Чтобы обновить контент в будущем — просто перетаскивай папку заново
   (Netlify сам заменит файлы), либо подключи GitHub-репозиторий для
   автодеплоя при каждом commit.

## Деплой на GitHub Pages

1. Создай новый репозиторий на GitHub и залей туда содержимое папки
   `cs2-cheatsheet` (файлы должны лежать в корне репозитория, не во
   вложенной папке).
2. В репозитории: **Settings → Pages → Source** — выбери ветку `main` и
   папку `/ (root)`.
3. Через минуту сайт будет доступен по адресу вида
   `https://твой-логин.github.io/имя-репозитория/`.
4. Любой новый `git push` с изменениями в JSON-файлах обновит сайт
   автоматически.

## Как расширять дальше

- **Печатная версия.** Добавь в `css/style.css` блок `@media print { ... }`,
  который прячет `.topbar`, `.toolbar`, `.tabs` и показывает все раскидки
  сразу одним списком — получится PDF-шпаргалка на распечатку.
- **Заметки/чек-листы.** Можно добавить `localStorage`-хранилище (при
  локальном использовании, не в среде с ограничениями на него) — чтобы
  отмечать галочками выученные раскидки.
- **Простая админка без сервера.** Есть бесплатные инструменты вроде
  [CloudCannon](https://cloudcannon.com) или
  [Decap CMS](https://decapcms.org), которые дают удобный веб-интерфейс
  для редактирования JSON/Markdown файлов в GitHub-репозитории — без
  необходимости писать свой бэкенд.
- **Авторизация.** Если захочешь закрыть сайт от посторонних —
  Netlify предлагает встроенную защиту паролем на платных планах, либо
  можно поставить Netlify/Cloudflare Access перед сайтом.
- **Видео вместо ссылок на YouTube.** Если видео свои — можно захостить
  их на Cloudflare Stream / Bunny.net и просто заменить `<iframe>` в
  `js/map.js` на `<video>` тег.

## Технологии

Чистый HTML + CSS + JavaScript (без фреймворков, без npm, без шага
сборки). Это осознанный выбор: минимум зависимостей, максимум
понятности кода и минимум того, что может сломаться при обновлении
инструментов.
